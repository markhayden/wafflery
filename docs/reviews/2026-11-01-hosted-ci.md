# Hosted browser failure investigation

Branch `fix-hosted-browser-races`, based on `cfedfb3`.
[Hosted run 41355373149](https://github.com/markhayden/wafflery/actions/runs/41355373149)
passed through browser installation, then failed the events test in Chromium/WebKit and the
pipeline test in WebKit. All failures waited for `Contract evidence: complete.` The run had no
uploaded artifacts; its log alone cannot distinguish incomplete preservation from stale UI.

## Evidence and scope

The initial local reproduction ran both specs five times in each engine: all 20 passed.
Review found no demonstrated lost-invalidation path for these normal/slow peer scenarios.
The assertions already wait on observable completion. No assertion, retry, deadline or product
behavior has been changed speculatively. The hosted root cause remains unconfirmed.

The browser host fixture now attaches a bounded read-only summary of attempt execution,
preservation, notices, result status and error code **before shutdown**. Shutdown can otherwise
change unfinished attempts. It does not attach the database, inputs or full recorded calls.
Fixture cleanup remains in a finally block even if diagnostics fail.

CI uploads only failure traces, screenshots, error context and these summaries, using the pinned
upload-artifact v6 action and three-day retention. The CI suite uses disposable offline roots;
browser credentials in a trace belong to the stopped temporary host, not provider accounts.
Real-tool probes remain opt-in and are not configured in CI. No arbitrary workspace/library
directory is uploaded. The owner explicitly requested these failure artifacts, superseding the
initial CI plan's no-upload choice.

## Follow-up and rollback

The coordinator pushes and observes the next hosted run. If it fails, inspect the attempt summary
first: incomplete with notices identifies preservation failure; a complete saved attempt with
stale DOM identifies client refresh/selection; pending identifies unfinished work. The matching
trace supplies request/timing and DOM evidence. Add a deterministic regression and fix the
demonstrated cause, preserving zero retries and current deadlines.

Revert the diagnostic workflow/fixture changes independently; runtime and data are unaffected.
No shared contract, sibling repository, release, push or tag changes are included.

## Rerun 41357299928: events-test cause and correction

[The diagnostic rerun](https://github.com/markhayden/wafflery/actions/runs/41357299928)
failed only events, in both browsers; pipeline passed. Each pre-shutdown summary showed execution
running, preservation pending and no result/error. Traces showed ongoing successful state and
attempt reads. Progress advanced to 18 in Chromium and 16 in WebKit before assertion expiry.
The peer's nominal 10-second delay counts 200 sleeps of 50 ms, notifying every ten sleeps;
completion requires progress 21 before image processing. Those batches took approximately
0.8–1.3 seconds on the hosted runner. The test deadline raced a deliberately delayed fake result,
while the receiving tab continued to follow the run correctly.

The events peer now has an explicit `held` scenario. It reports waiting, remains cancellable,
sends periodic heartbeats, and consumes a release file in its disposable workspace before
completing. The browser test
observes running/progress in the second tab, closes the first tab, then writes the signal.
No production behavior, browser assertion deadline or retry setting changed. This also prevents
a fast machine from completing the fake work before the intended tab closure.

The revised browser test failed before peer support was added (missing waiting progress), then
passed with the handshake. Wire cancellation coverage exercises both slow and held scenarios.
Review approved the implementation and evidence. The first local stress attempt overlapped Rust
builds, causing two fixture-setup timeouts on Cargo's build lock; that attempt was interrupted
and the verification rerun with builds finished. These were not completion-assertion failures.

Final verification runs under the shared heavy-check lock to exclude sibling build contention.
The 20 repetitions per browser of events/pipeline passed all 80 cases with zero retries.
The full browser suite passed 70 cases, with four existing opt-in skips. Formatting, clippy,
72 Rust tests (three existing opt-in ignores), typecheck, 12 UI unit tests, two asset-tooling
tests, Storybook, asset freshness/reproducibility and the release build all passed. Generated
assets and lockfiles remained unchanged. The final heartbeat refinement also passed review. The original pipeline
failure remains unconfirmed: it had no artifacts and did not recur in the diagnostic hosted run.
Failure capture remains enabled. Hosted confirmation of this correction still requires a push.
