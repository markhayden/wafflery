Round 1 isolated three shared-interface questions: render executable resolution (Q-R), invalid
estimate error shape (Q-E), and document output location/assets (Q-D). These were scoped gates,
not a reason to block all work. They are now settled below. Minimal environment/default lookup and the one-shot MCP probe
are host choices within the contract; no additional CLI contract is required for them.

The suggested automatic force-kill for a stuck viewer was not adopted: existing explicit-force
ownership policy remains until deliberately changed. The suggested loopback-port wildcard CSP
was replaced with an exact-origin wrapper so opening reports does not authorize unrelated ports.

## Round 2

Round 2 confirmed all five high-severity findings were addressed. Its verdict requested four
medium-severity text corrections before approval with the named gates. All four are applied:

- V06b requires full input coverage only on completed runs. Non-completed runs may report an
  ordered subset; check roles and identities, preserve the outcome and note missing evidence.
- V11 distinguishes a new session id from ordinary ledger changes. V13/V-B test budget depletion
  with unchanged credential readiness; a separate present-to-valid case invalidates the quote.
- V17a places the sandbox only on the cross-origin report iframe, with allow-scripts and
  allow-same-origin. The trusted wrapper retains its host origin, a single-use scoped URL grant
  and no-referrer policy. Top navigation, forms, popups and downloads stay disallowed.
- V04a treats requirement names as displayable data; only eligible environment identifiers are
  forwarded. Unknown/non-identifier or excluded names do not invalidate a conforming description.

Lower-severity refinements also landed: restart repeats the config probe; viewer process groups
and stuck slots are explicit; estimates have a separate 30-second deadline and no automatic
retry; fixed-PATH helper compatibility is a real-peer check; corrected paid attempts need new
preparations/estimates; task dependencies and the review commit name are current.

The two rounds completed successfully as read-only CLI reviews. No third review or new runtime
test pass is claimed. These are planning findings and dispositions, not implementation evidence.

`e503a238ad6cc833834891c2c2cece7152b08bfc`. The final plan was checked against that revision's
CONTRACT.md and description, estimate and refusal schemas after round 2 completed:

  absolute command[0] is forbidden. Placeholders substitute only whole argv elements.

  reads only that file under a per-render grant; it does not assume existing image roots, serve
  neighbors or delete the source. Server EOF/SIGTERM exits zero and renders never modify run.dir.

  cannot block a free call. A needed missing/invalid requirement returns not_ready before a run,
  releasing the claim; credential means an in-run provider 401/403 only.
- Both credential and non-secret env requirements participate in startup. Defaults count toward
  config identity. CLI estimates have null sessions and cannot authorize MCP execution. Delivery
  flags return_images/image_blocks are excluded from the tool's opaque binding.
